# Правила участия в проекте

Для внесения изменений в проект рекомендуется придерживаться следующих правил.

## Ветки

Для каждой отдельной задачи создавайте новую ветку от `main`.

Пример:

```bash
git checkout -b feature/task-name
```

Названия веток должны быть короткими и понятными.

Примеры:

* `feature/add-docker`
* `fix/readme`
* `docs/update-contributing`

## Коммиты

Один коммит должен содержать одно логически завершённое изменение.

Сообщение коммита должно кратко описывать внесённые изменения.

Примеры:

```text
Add Docker configuration
Fix README instructions
Update Git setup guide
```

## Pull Request

Изменения в `main` вносятся через Pull Request.

Перед созданием Pull Request необходимо:

* проверить, что изменения работают;
* убедиться, что в коммит не попали временные или конфиденциальные файлы;
* кратко описать внесённые изменения.

## Конфиденциальные данные

Не добавляйте в репозиторий:

* пароли;
* токены;
* приватные SSH-ключи;
* `.env` файлы с секретами;
* другие конфиденциальные данные.

Для таких файлов необходимо использовать `.gitignore`.

## Обновление локального репозитория

Перед началом работы рекомендуется получить последние изменения:

```bash
git pull
```

## Общие правила

Старайтесь делать изменения небольшими и понятными, использовать осмысленные названия файлов, веток и коммитов и не добавлять в репозиторий лишние файлы.
